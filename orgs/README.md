# orgs/

Everything specific to one Beacon account lives in its own `orgs/<slug>/`
folder. Nothing under `orgs/` (other than this file) is tracked in git —
see `.gitignore` — because none of it is generic: it's one charity's
credentials, colours, logo and editorial knowledge of its own CRM.

**Run `python run.py` from the repo root to create or pick up an
organisation — it's a wizard and writes everything below for you.** This
file documents what it creates, for when you want to understand or
hand-edit the result.

Everything for one org — inputs and generated output alike — lives under
its `orgs/<slug>/` folder, so a single gitignore rule covers all of it:

```
orgs/<slug>/
  .env.local          BEACON_API_KEY=...
                       BEACON_ACCOUNT_ID=...
                       Created with empty placeholders by run.py; add the
                       real values yourself, this file is gitignored.

  beacon-schema-raw.json   Cache of GET /entity_types. run.py fetches this
                           itself once .env.local has a real key. To
                           refresh after a schema change, delete this file
                           and run run.py again.

  branding.json        Report colours and logo. run.py asks for these when
                        creating a new org (Enter to skip any of them):
                        {
                          "name": "Organisation Name",
                          "primary": "#123456",
                          "secondary": "#abcdef",
                          "coral": "#...", "teal": "#...", "green": "#...",
                          "lime": "#...", "sun": "#...",
                          "logo_white": "https://.../logo-white.svg",
                          "logo_purple": "https://.../logo-colour.svg"
                        }
                        Missing entirely, or missing individual keys: falls
                        back to build_report.py's neutral DEFAULT_BRANDING.
                        Logo values: a full https:// URL is used directly —
                        prefer this, since the generated report needs to
                        work as a standalone file sent to someone with no
                        access to this project or its assets, and a live
                        URL keeps the file small. A local filename (no
                        scheme) is read from assets/ and embedded as a
                        base64 data URI instead, for an org with no public
                        logo to link to. No logo at all: the report renders
                        the org name as plain text in the header.

  assets/               Only needed for a local (non-URL) logo — see above.

  taxonomy.py           Editorial grouping of this account's record types
                         into families (GROUPS, MEMBERSHIP, PENDING_SOON,
                         LABEL_WARNINGS). run.py writes a minimal stub
                         (one catch-all "admin" group, everything ungrouped)
                         — the pipeline runs fine with it as-is, it just
                         won't have editorial colour/commentary. Fill it in
                         once you've seen the real schema.

  semantics.py           Editorial notes on what specific fields mean in
                          practice (FIELD_NOTES, TYPE_NOTES, render()).
                          run.py writes an empty stub; same idea.

  out/                  Generated by build_schema.py: schema.json,
                         relationships.json, attachments.json, semantics.md
                         — the machine-readable deliverable.

  reports/               Generated by usage_report.py (optional): usage.json,
                          usage-summary.md — record counts and option usage.

  beacon-report.html     Generated by build_report.py — the human-readable
                          report. Safe to send to someone standalone; it
                          doesn't depend on anything else in this repo once
                          built (see branding.json's logo note above).
```

## Getting a new org running

Run `python run.py`, pick "set up a new organisation", answer the prompts.
It creates the folder above, tells you where to put the real API key, and
stops there. Run it again once the key's in — it fetches the schema and
offers to build the export and report. Rerun any time after that to rebuild
either one.
